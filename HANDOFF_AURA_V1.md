## 2. Текущее состояние

- **Работает на стендовом Pi:** постоянный сервис `aura-v1.service` (автозапуск, `Restart=on-failure`,
  ≤ 5 перезапусков за 5 мин, `Conflicts=aura.service`). После загрузки Аура спит: микрофон читается только
  на Pi, в облако ничего не уходит. Агент владельца в Yandex AI Studio, модель `speech-realtime-260528`
  (константа `AGENT_MODEL` в `aura/config.py`, без запасных).
- **Голос по нажатию:** `s`/пробел в панели → «ГОВОРИТЕ» → серверный VAD → ответ через HDMI на телевизор;
  7 с на уточнение без нажатия; «не услышала речь» с уровнем микрофона. Акустическая петля 12/12.
- **Выход из панели** только отключает её: Аура работает дальше и засыпает сама; остановка — `aura stop`.
- **Микрофон выдернули и вернули** — Аура замечает через 2 с и сама поднимается спящей (≈ 5 с).
- **Микрофон стенда** слышит обычный голос только вблизи — ограничение железа (адаптер AB13X со своей
  голосовой обработкой, замеры в `FINDINGS.md`); владелец решил пока оставить его.
- **Инструменты агента:** время/дата, погода и поиск (Yandex generative search тем же ключом),
  `get_vehicle_status` — заглушка «диагностер OBD2 не подключён». Погода домашнего города
  запрашивается по нажатию и кэшируется на 30 мин: ответ ≈ 1–1,6 с после конца фразы.
- **Legacy Aura:** остановлена и отключена (`aura.service` inactive/disabled), файлы и юнит не тронуты.
- **Версия на Pi:** метка `aura-v1.0` (`aura status` показывает коммит; откат к метке — `docs/PI_MIGRATION.md`, 4.1).
- **Голосовая проверка владельцем** (2026-09-25): проведена; итоги — в `CURRENT_STATE.md`.

## 3. Что существует только на ноутбуке и Pi (не в git)

### Ноутбук (Windows 10), `%USERPROFILE%\.aura\`

| Путь | Что это |
|---|---|
| `aura-v1.env` | секреты и локальные настройки: `YANDEX_CLOUD_API_KEY`, `YANDEX_CLOUD_FOLDER_ID`, `YANDEX_AGENT_PROMPT_ID`, `AURA_CONTROL_TOKEN` (токен канала управления), `AURA_HOME_CITY` (город для погоды). Копируется на Pi командой `aura install`. |
| `ssh\aura_pi_ed25519` (+ `.pub`) | отдельный SSH-ключ агента для Pi (без парольной фразы) |
| `ssh\config` | SSH-алиас `aura-pi`: `HostName` (текущий адрес Pi — меняется автоматически), `HostKeyAlias aura-pi`, пути в кавычках |
| `ssh\known_hosts` | ключ хоста Pi под именем `aura-pi` (опознание Pi не зависит от адреса) |
| `ssh\pi.mac` | MAC Wi-Fi Pi — ускоряет поиск Pi в подсети |
| `ssh\install_key.ps1` | одноразовый скрипт, которым владелец положил публичный ключ на Pi |
| `bin\aura.cmd` | команда `aura`: ставит `PYTHONPATH` на `wayaura-core\aura-v1` и запускает `python -m panel` из venv репозитория; каталог `bin` добавлен в пользовательский `PATH` командой `aura install` |
| `backups\pi-legacy-20260923\` | бэкап Legacy с Pi до переноса: `aura-0.1.tar.gz`, `etc-systemd-aura.tar.gz`, `pi-wayaura-core.tar.gz`, `pi-wayaura-core.bundle`, `manifest-pi.txt`, `SHA256SUMS` (содержит секреты Legacy — не выкладывать) |
| `test\*.wav` | синтезированные тестовые фразы (16/24/44,1/48 кГц, длинная фраза, `weather_24000.wav` — «Какая сейчас погода?») |
| `work\pi-restore\` | распакованный бэкап, из которого New Aura пушилась на GitHub; можно удалить |

Ещё на ноутбуке: `wayaura-core\aura-v1\.venv` (Python 3.13, ставился через winget для пользователя),
`wayaura-core\aura-v1\runs\` (логи зонда Milestone 0, в `.gitignore`), `%LOCALAPPDATA%\aura-docs\`
(клоны примеров Yandex для справки; можно удалить).

**Как Pi находится при смене адреса** (`panel/pi.py`, `docs/NETWORK.md`): сохранённый адрес → `aura.local`
(на Windows 10 почти не работает) → перебор порта 22 в подсети ноутбука (сначала MAC Pi). Кандидат
принимается, только если совпал ключ хоста (`HostKeyAlias aura-pi`); новый адрес записывается в
`ssh\config`. Проверено: раздача телефона сменила подсеть — Pi нашлась за ≈ 20 с.

## 4. Незавершённое, открытые вопросы, известные проблемы

- **Обычный голос с 1–1,5 м не слышен — железо** (разобрано 2026-09-25, `FINDINGS.md`): цепочка
  микрофон + AB13X сама обрабатывает голос, тихая речь теряет согласные; не хватает 20–25 dB. Усиление,
  порог VAD, регулятор записи не помогают. Владелец пока оставил микрофон. Для нового микрофона готовы
  `AURA_MIC_GAIN_DB`, `AURA_VAD_THRESHOLD`, команда `tune`, `tools/loopback.py --level-db/--noise`.
- **Приветствие агента звучит перед ответами** — строка в инструкциях агента «в самом начале агент всегда
  говорит одно и то же - <фраза>». Каждое пробуждение Ауры — новая сессия, то есть «начало» для модели.
  Текст замены подготовлен (у владельца в отчёте этапа 2): приветствие — только в ответ на приветствие
  или вопрос «кто ты», перед ответами — никогда. Менять агента может только владелец.
- **Погода для других городов и общий поиск** по-прежнему ждут поиска Yandex (1–8 с); прямой погодный
  источник — новый поставщик, только с согласия владельца.
- **Ключ Yandex не перевыпущен** (проходил через чат).
- Полудуплекс: перебить Ауру голосом нельзя (только `s` или `x`).
- Стоимость по тарифу не сверена.
- Следующий этап по плану владельца: слово-активация «Аура» (Vosk, затем при необходимости openWakeWord).

## 5. Грабли (неочевидное)

- **PowerShell 5.1 и SSH:** внутренние кавычки в аргументах пропадают, в канал (`| ssh … bash -s`)
  добавляются BOM и `\r`. Команды на Pi — через `aura log`/`aura status` или скрипт в base64
  (`docs/DIAGNOSTICS.md`).
- **USB-адаптер AB13X** не переносит программное отключение (`authorized=0/1`) — после него ошибка
  ввода-вывода до сброса USB. Переподключение для проверок имитировать сбросом USB (`FINDINGS.md`).
- **Регулятор записи AB13X** (`Mic Capture Volume`) на уровень речи не влияет; его значение 108
  восстанавливает система после переподключения.
- **Кодировка `.ps1`:** Windows PowerShell 5.1 читает UTF-8 без BOM как cp1251 — кириллица в скрипте
  превращается в кракозябры (так «синтезированная фраза» оказалась мусором). Сохранять `.ps1` с BOM.
- **Пробел в имени пользователя Windows:** пути в `ssh\config` — в кавычках (`"~/.aura/..."`), иначе
  `IdentityFile`/`UserKnownHostsFile` ломаются; в `GIT_SSH_COMMAND` — тоже кавычки.
- **Пользоваться Windows OpenSSH** (`C:\Windows\System32\OpenSSH\ssh.exe`) с `-F ~/.aura/ssh/config`;
  git-bash `tar` понимает `C:` как удалённый хост — нужен `--force-local`.
- **Энергосбережение Wi-Fi на Pi** (по умолчанию включено) — Pi «пропадала» на минуты, не отвечая даже
  на ARP. Выключено; при новой установке/сети проверить `/usr/sbin/iw dev wlan0 get power_save`.
- **Pi не ходит на GitHub по SSH** с раздачи телефона (порт 22 наружу закрыт) — поэтому `aura deploy`
  доставляет код с ноутбука по SSH-каналу панели, а не `git pull` на Pi.
- **Раздача телефона меняет подсеть** — отсюда поиск Pi по ключу хоста (раздел 3).
- **API Yandex Realtime:** 48 кГц не принимает (AB13X умеет только 48 кГц → ресемплинг в коде);
  `input_audio_buffer.clear` рвёт сессию; ручной конец фразы ненадёжен; на `260528` функции вызываются
  только со строгой схемой (`additionalProperties: false`), встроенный `web_search` не работает;
  расшифровки на `260528` — по одной фразе (не накопительно).
- **HDMI держит сервис:** пока `aura-v1` работает, отдельный процесс не видит `vc4-hdmi` — проверки
  спрашивают статус у сервиса. Тестовый вывод через телевизор — только командой `loopback` сервиса.
- **Команды от нескольких клиентов** (`start/stop/listen/ask`) сериализуются — не убирать блокировку.
- **`subprocess`/SSH из панели** — всегда с таймаутом: код 255 = нет связи, не «не установлено».
- Секреты в журнале: `events.py` пишет только длины текстов; `Settings.redact` скрывает ключ, каталог,
  ID агента и токен в сообщениях об ошибках.

## 6. Быстрые команды (ноутбук, PowerShell)

`aura` (панель), `aura status`, `aura log` (только чтение), `aura deploy`, `aura stop`, `aura restart`, `aura install`,

юнит-тесты — см. `aura-v1/README.md`.
