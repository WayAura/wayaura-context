# Эпоха Aura v1 на Raspberry Pi — завершённый исторический этап (2026-09-23 … 2026-09-27)

**Статус: закрыта 2026-09-27 решением владельца.** Raspberry Pi убрана из продукта. Новая связка — телефон с
приложением + OBD-адаптер + облачный сервер Ауры в Yandex Cloud. Действующая работа идёт в новых
репозиториях `WayAura/wayaura-private` (команда) и `WayAura/wayaura-public` (публичное описание);
этот репозиторий и `wayaura-core` — история, не переписываются.

## Что было сделано

| Этап | Результат |
|---|---|
| 1 (23–25.09) | Aura v1 на агенте владельца в Yandex AI Studio (Realtime API, `speech-realtime-260528`): постоянный сервис на Pi, голос по нажатию с окном уточнения 7 с, инструменты агента (время, погода, поиск, заглушка OBD2), панель `aura` на ноутбуке, правило «одна Аура без подмен», Legacy остановлена |
| 2 (25–26.09) | выход из панели = отключение клиента; восстановление после пропажи микрофона и вывода звука; погода ≈ 1–1,6 с (предзагрузка, кэш); разбор чувствительности микрофона; `aura log`; метка `aura-v1.0` |
| 3 (26.09) | голос с клиента (телефон, имитация — ноутбук) по каналу управления; проект связки «Аура + телефон + OBD2» (`wayaura-core/aura-v1/docs/PHONE_LINK.md`); вызов функции текстом сужен до старой инструкции агента |
| Отдельно | слово «Аура» на Pi (Vosk) — ветка, в конце влита в `main` PR #9, по умолчанию выключено; ненадёжно на микрофоне стенда |

## Что выяснено (опыт, который переносится в новый проект)

- **Realtime API Yandex:** 48 кГц не принимает (16/24/44,1 — да); `input_audio_buffer.clear` рвёт сессию;
  ручной конец фразы ненадёжен (сервер сам отменяет ответы) — нужен серверный VAD; функции на `260528`
  вызываются только со строгой схемой, встроенный `web_search` не работает; расшифровки — по одной фразе;
  прерывать ответ надо на своей стороне (звук приходит пачкой, `response.cancel` опаздывает).
- **Пауза конца фразы 0,8 с** (VAD агента) обрывает человека на полуслове; уменьшение порога VAD на
  чувствительность не влияет.
- **Сказанное во время ответа** нельзя отправлять позже: была ошибка — слово, сказанное пока Аура говорила,
  получило отдельный ответ после неё.
- **Приветствие в инструкции агента** «в самом начале всегда говорит…» звучало перед каждым ответом и ломало
  вызов функций (писался текстом). Ответы должны быть короткими по умолчанию.
- **Погода:** генеративный поиск 1,7–8 с; ускоряют предзагрузка и кэш; для произвольного города нужен
  погодный источник.
- **Звук на стенде:** USB-адаптер с «гарнитурной» обработкой не слышит обычный голос с 1–1,5 м (железо);
  HDMI-вывод может появиться позже сервиса; телевизор иногда молчит сам. Слово «Аура» на малой модели Vosk
  через такой микрофон не распознаётся (0–1 из 10), на чистом звуке — 40 из 40 без ложных срабатываний.
- **Телефон как главный вход:** приложение не может само включить раздачу (Android/iOS), микрофон в фоне
  нельзя запустить из фона (Android) и начать из фона (iOS) — эти выводы учтены в новом плане (сессию
  запускает пользователь).

## Почему закрыта

Новая архитектура продукта (решение владельца 2026-09-27): без Raspberry Pi — телефон ведёт поездку и звук,
OBD-адаптер отдаёт данные, облачный сервер Ауры держит диалог, инструменты и память; ключи Yandex — только
на сервере. Незакрытые проблемы эпохи Pi (микрофон стенда, ввод текстом в панели) не чинятся — уроки
из них перенесены в новый проект как требования.

## Где лежит и как вернуться

| Что | Где |
|---|---|
| Код Aura v1 | `WayAura/wayaura-core`, папка `aura-v1/` |
| Финальное состояние эпохи | метка **`aura-v1-pi-final`** = `main` 8421538 (этапы 1–3 + слово «Аура») |
| Проверенная версия на Pi | метка **`aura-v1.0`** = 7b199da (без слова «Аура»; этот код остаётся на Pi) |
| Документы эпохи | этот репозиторий: `AURA_V1_RULES.md`, `HANDOFF_AURA_V1.md`, `CURRENT_STATE.md`, `MIGRATION_CHECKPOINTS/AURA_V1_*` |
| Pi | сервис `aura-v1` остановлен и выключен из автозапуска (2026-09-27); Legacy тоже выключена; файлы, код, модели и `~/.aura/aura-v1.env` не удалялись |

Вернуться к метке и снова запустить Ауру на Pi (PowerShell, на ноутбуке, из `wayaura-core`; ноутбук и Pi
в одной сети):

```powershell
git fetch --tags origin
git switch -c pi-final aura-v1-pi-final          # или aura-v1.0 — проверенная версия без слова «Аура»
aura deploy                                        # код на Pi = этот коммит
ssh -F "$env:USERPROFILE\.aura\ssh\config" aura-pi "sudo systemctl enable --now aura-v1.service"
aura status                                        # версия на Pi = git rev-parse --short 'aura-v1-pi-final^{commit}'
```

Остановить снова: `ssh -F "$env:USERPROFILE\.aura\ssh\config" aura-pi "sudo systemctl disable --now aura-v1.service"`.
